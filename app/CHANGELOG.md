# Changelog

## Unreleased

- Fixed: invalid `propose_mutation` requests over the HTTP/CLI surface now return `400 invalid_input` with the exact validation message. They previously returned an origin `502`; Cloudflare replaced that JSON response with plain `error code: 502`, making a missing `title` or `reason` look like an edge-routing outage.
- New: search can be scoped to timeline attention tiers. `search` (MCP + HTTP + `pdw search --priority self,direct`) and the SQL functions `timeline.search_text` / `search_text_exact` / `search_hybrid` take a trailing `priorities text[]`, and every hit now carries its own `priority`. The tier is pushed into every scan rather than applied to the results, so a narrow tier still gets a full top-k; an unknown tier errors listing the valid set, and omitting it (or passing an empty array) searches everything exactly as before.
- Breaking (HTTP API): `POST /api/tools/{name}` now rejects unknown request fields with `400 invalid_input`, naming the unknown field and the valid ones. It previously ignored them and answered `200` with an unfiltered result -- so `{"query":"x","priority":"self"}` returned a confident, authoritative-looking answer to a question nobody asked. MCP already validated this way; the two surfaces now agree.
- Performance: `timeline.search_text_exact` scopes `parallel_setup_cost`/`min_parallel_table_scan_size` around its ILIKE recheck only. The trigram index answers in ~170ms and the recheck then detoasts every candidate document single-threaded; on the production corpus `admin/api-keys` went from 4285ms to 883ms (8 workers, identical buffers and rows).
- Performance: the Postgres pool is bounded (25 open / 10 idle / 30m lifetime) instead of unlimited-open and 2-idle, and the hybrid path now overlaps its `search_hybrid` catalog probe with the embedding request instead of running them back to back.
- New: `pdw search [flags] QUERY...` provides first-class hybrid CLI search using the same implementation as the MCP `search` tool, with compact text output and clean `--output json`. MCP now directs text lookups to search before schema discovery, the default response is bounded to 20 hits, and responses include explicit zero-result/drill-down guidance. Generic CLI `call` also exits non-zero when a tool returns a top-level soft error instead of printing an error-shaped success.
- Breaking: `get_object` now returns a signed, time-limited `download_url` (plus `expires_at`) instead of inline `content_base64`/`content_omitted`. The link is served by a new unauthenticated-but-HMAC-verified `GET /objects/{storage_file_id}?exp=...&sig=...` endpoint, so it can be opened straight from a chat or browser. Link lifetime is `PDW_OBJECT_URL_TTL` (default 1h); `PDW_OBJECT_STORE_MAX_OBJECT_BYTES` now caps what the endpoint will serve (default raised 5MB → 100MB).
- Breaking: every client must now identify itself with a name that gets logged on every request, so it's possible to tell connectors apart (claude vs. codex vs. hermes, etc.).
  - HTTP API: `Authorization: Bearer <client_name>:<PDW_SECRET_TOKEN>`. A bare `Bearer <token>` is rejected with 401.
  - MCP OAuth: the authorize page has a new required `Client name` field alongside the secret. The name is embedded in the issued access/refresh tokens; existing tokens minted before this change are rejected and must be re-authorized.
  - The name appears as `client=<name>` on the per-request log line, on MCP tool-call logs, and on API tool-call logs.
- New: HTTP API at `/api/tools` (list) and `POST /api/tools/{name}` (invoke). Every MCP tool is exposed; same input/output, `{data: ...}` / `{error: {...}}` envelope. Static-bearer auth via `PDW_SECRET_TOKEN`. The query cache is shared with MCP — a `query_id` minted on one surface is fetchable on the other.
- New: `PDW_SECRET_TOKEN` is the preferred env var for the shared secret. `MCP_SECRET_TOKEN` is still read as a fallback for one release.
- Internal: MCP and HTTP both consume a shared `tool.Registry`. No MCP-visible behavior change: tool names, descriptions, input schemas, and call results are byte-identical (regression-tested via golden snapshot).
- Breaking: redesigned `query` to return cached `query_id` cursors plus preview/truncation metadata. Substring-based SQL pagination for long fields is no longer supported; callers should use `get_field`, `get_rows`, and `grep_rows`.
